# 木版年画刻版工序档案

## 项目简介

面向木版年画作坊的纯前端工序档案应用。它把画稿、分版、刻版、修版与套色印制过程串成可追溯的本地记录，便于刻工与印制管事按套色序号协作。

## Docker 一键启动

首次启动先复制环境配置，再构建并启动容器：

```bash
cp .env.example .env && docker compose up -d --build
```

停止服务可执行：

```bash
docker compose down
```

## 数据存储说明

数据全部写入浏览器 IndexedDB，不依赖后端服务。数据库名为 `gbwoodprint-db`，当前结构版本为 `3`。

- `version(1)` 建立画稿、版片、刻工、印制批次、工序节点五张表及常用查询索引。
- `version(2)` 为各表回填 `schemaRev: 2`，便于后续迁移识别数据结构。
- `version(3)` 新增木料段（`woodLogs`）、裂纹工单（`cracks`）、批次复核（`batchReviews`）三张表；版片增加木段挂接与重刻谱系字段，批次增加复核状态；老库升级时自动把种子版片补挂到对应木段，存量批次置为「正常」。
- 首次创建数据库时通过 Dexie 的 `populate` 回调写入四类画稿、四段木料（三段梨木、一段黄杨）、完整基础版片（已挂木段）、四名刻工、印制批次与多条工序节点。
- 刷新页面不会丢失数据；清除浏览器站点数据会同时清除本地档案。

## 木料段追溯与裂纹处置

- **木段登记与挂段**（`/woodlogs`）：进料木段逐段登记编号、木质与内裂备注；已开版片逐块挂到木段，未挂段版片在页面顶部集中补挂。挂段变更会令木段版本号（`woodVersion`）自增。
- **裂纹上报按木段定范围**（`/cracks`）：裂纹在任一版片出现，提交时单事务沿木段一次性处理：
  - 关联范围 = 同木段全部版片（含已停用旧版）及其工序节点、波及画稿下全部印制批次，跨画稿也不漏；不按版片现状缩小范围，避免已印批次漏复核。
  - 未刻版片转「待换料」；已刻/在刻版片保留状态，已刻工序节点保留不删。
  - 关联批次转「待复核」并记录所归裂纹工单。
- **工单处置留依据**：重刻——旧版停用并留别名（`alias`），另刻新版回指旧版，新旧版在工序页通过重刻谱系互查，已刻节点仍挂旧版；沿用原印样——木段停用、待换料版片恢复待刻。两种方式都必须填写依据与处置人。
- **批次逐批复核**：每批可结论「重刻」或「沿用原印样」，复核依据、复核人写入 `batchReviews` 后该批才解除待复核。
- **并发与可靠性**：提交带木段乐观锁版本号与客户端幂等令牌（`clientToken`）。两个标签页同时提交同一木段裂纹时，后提交者先看到冲突（木段版本已变 / 已有待处理工单），不产生第二条工单；写入异常时事务整体回滚、不留半套换料记录，提交落入「待处理写入」队列，可凭原令牌重试，重复提交自动幂等。跨标签页通过 BroadcastChannel 通知刷新。

## 核心功能与路由表

| 路由 | 页面 | 主要能力 |
| --- | --- | --- |
| `/drafts` | 画稿总览 | 按题材与状态筛选，查看版片刻成进度和最近印制批次，内联新建画稿 |
| `/drafts/:id/blocks` | 版片编排台 | 按套色序号排列表格，指派刻工、校验序号、标记刻成、查看所属木段与重刻别名 |
| `/blocks/:id/nodes` | 工序节点时间线 | 推进或回退工序节点，登记操作人、时间与耗时，查看重刻新旧版谱系 |
| `/batches` | 印制批次登记 | 登记纸张、颜料、印数，逐版填写套色偏差，查看批次待复核状态 |
| `/woodlogs` | 木料段追溯 | 登记木段来源与内裂备注，版片挂段/摘段，查看本段版片去向 |
| `/cracks` | 裂纹工单台 | 沿木段上报裂纹并预览影响范围，冲突提示、待处理重试、工单处置与批次逐批复核 |
| `/carvers` | 刻工档与版片分布 | 按专长筛选，查看在刻版片数、节点平均耗时与当班分布 |
| 其它 | 画稿总览 | 已实现 history 路由到画稿总览的回退 |
